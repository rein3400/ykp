  Design: POS Individual Receipt + Warehouse Evidence

  1. Finance POS — Individual Receipt

  Schema baru:
  fin_pos_receipts
    receipt_id (PK)
    date, brand_id, outlet_id
    receipt_number
    gross_sales, discount, refund, void, tax, service_charge
    net_sales
    payment_method_id + amount (jsonb)
    transaction_time, cashier, shift
    source (moka/manual)
    source_ref (e.g. Moka receipt id)
    notes
    photo_url
    verified_by, verified_at
    recorded_by, recorded_at
    created_at, updated_at

  fin_pos_daily → MATERIALIZED VIEW dari fin_pos_receipts
    (atau virtual view, dipilih berdasarkan performance)

  Perubahan import:
  - parseMokaCsv sekarang return per receipt, bukan aggregate.
  - CSV import insert ke fin_pos_receipts, satu baris per struk.
  - fin_pos_daily otomatis update lewat view.

  UI POS:
  - /pos tetap nampilin daily aggregate, tapi bisa expand per row → list
  receipt.
  - Tambah button "Tambah Struk" dengan form + upload foto nota.
  - Per receipt: foto, status verified, siapa verify.
  - Upload pakai Supabase Storage (bucket pos-receipts).

  Anti-fraud signals:
  - Receipt total yang ga sesuai foto = flag.
  - Receipt duplicate (receipt_number + outlet + date) = flag.
  - Receipt edit setelah verified = butuh alasan + audit trail.

  2. Warehouse — Evidence on All Transactions

  Tambahan kolom di schema warehouse:
  evidence_urls: jsonb[] (multiple foto/video per transaksi)
  recorded_by, verified_by

  Diterapkan di:
  - receiving
  - stock_issue
  - transfer (dispatch + receive)
  - waste
  - stock_count/opname

  UI Warehouse:
  - Tiap form transaksi ada section upload bukti (drag-drop + preview).
  - Bisa upload multiple file.
  - Video: preview thumbnail + playback.
  - Di list/approval view: tampil badge "evidence" + modal preview.

  Supabase Storage:
  - Bucket: warehouse-evidence
  - Path: warehouse/{transaction_type}/{transaction_id}/{filename}
  - Row-level security: user bisa baca yang outlet-nya sesuai.

  3. Shared patterns

  - File validation: max 10MB per file, image/video only, virus scan (kalau
  mau).
  - Compression: resize image jadi max 1920px.
  - Audit trail: setiap upload/verify tercatat di domain audit log.
  - Fallback: kalau upload gagal, transaksi tetap bisa tersimpan tapi status
  evidence_pending.
