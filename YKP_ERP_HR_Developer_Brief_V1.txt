DEVELOPER BRIEF — YKP ERP HR MODULE V1

1. PROJECT CONTEXT

YKP sedang membangun ERP internal untuk beberapa brand F&B:
- Funkydak
- Sekarpizza
- Suburbuns
- Laju Kopi
- Uncle Masala

Untuk tahap awal, HR Module akan memakai web app HR existing yang sudah pernah dibuat dan sudah running. Fokus utama bukan membangun ulang dari nol, tetapi:

Clone / lanjutkan HR Web App existing
→ ganti database/spreadsheet ke database YKP
→ isi master data karyawan YKP
→ migrasi aturan absensi, shift, payroll, bonus, dan potongan
→ test perhitungan
→ running untuk 1 brand / 1 outlet pilot

HR Module harus menjadi fondasi data SDM untuk seluruh YKP ERP dan nantinya menyediakan summary yang bisa dibaca oleh Orchestration Layer dan Hermez AI.


2. TUJUAN HR MODULE

HR Module harus menjadi pusat kontrol SDM YKP.

Fokus utama:
1. Menyimpan master data karyawan.
2. Mengelola absensi masuk dan pulang.
3. Mengelola shift dan roster.
4. Menghitung keterlambatan.
5. Mencatat izin, sakit, cuti, dan ketidakhadiran.
6. Menghitung payroll.
7. Menghitung bonus, lembur, potongan, dan kasbon.
8. Membuat slip gaji.
9. Menyediakan approval payroll.
10. Menyediakan HR daily summary untuk Orchestration Layer dan Hermez.
11. Menyediakan audit log agar semua perubahan bisa dilacak.


3. STATUS SAAT INI

HR App:
- Sudah ada.
- Sudah pernah running.
- Perlu diclone untuk versi YKP.
- Database/spreadsheet lama perlu diganti ke database YKP.
- Data dummy / data non-YKP harus dibersihkan.
- Aturan payroll perlu disesuaikan dengan kebijakan YKP.
- Perlu testing ulang dengan data karyawan YKP.

Database awal:
Untuk V1 boleh menggunakan:
- Google Sheet / Spreadsheet Database

Nanti jika sudah stabil, bisa migrasi ke:
- PostgreSQL
- Supabase
- Firebase / Firestore untuk kebutuhan real-time ringan

11. ALERT RULES HR V1

Rules awal:
- staff_late > 2 orang per outlet = MEDIUM
- staff_absent tanpa keterangan = HIGH
- incomplete attendance > 1 orang = MEDIUM
- shift shortage = HIGH
- late_minutes berulang 3 kali dalam 7 hari = MEDIUM
- payroll discrepancy = HIGH
- payroll belum approved mendekati tanggal gajian = HIGH
- overtime berlebihan = MEDIUM
- akun staff tidak aktif tetapi masih masuk roster = MEDIUM
- perubahan gaji tanpa approval = CRITICAL
- perubahan rekening mendekati payout = HIGH

12. WORKFLOW HR HARIAN

Pagi:
- Sistem membaca roster hari ini
- Karyawan check-in
- Sistem mendeteksi tepat waktu / telat
- Supervisor menerima alert jika shift kekurangan orang
- Opening staff dikonfirmasi

Siang:
- HR memantau absensi tidak lengkap
- Supervisor memproses shift swap / izin
- Overtime dicatat bila diperlukan

Malam:
- Karyawan check-out
- Sistem mendeteksi lupa checkout
- Rekap attendance dibuat
- hr_daily_summary dibuat
- Rules engine memeriksa alert
- Summary siap dibaca Orchestration Layer dan Hermez

Akhir periode payroll:
- Data absensi dikunci
- Adjustment diperiksa
- Payroll digenerate
- HR review
- Owner approve
- Finance menerima payout list
- Payment ditandai
- Slip gaji dibuat
