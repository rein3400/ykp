YKP AI ORCHESTRATOR / HERMES
DETAIL WORKFLOW UNTUK DEVELOPER
Versi 1.0

============================================================
1. TUJUAN SISTEM
============================================================

YKP AI Orchestrator / Hermes adalah pusat pengatur workflow AI untuk menghubungkan:
Telegram, TradingView Webhook, PostgreSQL, Redis, AI Model, ERP, HR, Finance, SOP, Dashboard, dan SRI ICT Trading Assistant.

Konsep:
User / Event -> Gateway -> Orchestrator -> Database / Tools / AI Model -> Response / Alert / Dashboard / Journal

============================================================
3. WORKFLOW TELEGRAM COMMAND
============================================================

Command awal:
- /status
- /omzet
- /hr
- /finance
- /sop
- /trading
- /report
- /help

Flow:
1. User kirim command ke Telegram.
2. Telegram Bot menerima update.
3. Sistem validasi Telegram user ID.
4. Sistem cek role user di PostgreSQL.
5. Command diparse.
6. Orchestrator menentukan module:
   /omzet -> Owner / Finance Engine
   /hr -> HR Engine
   /sop -> SOP Engine
   /trading -> Trading Engine
7. Module mengambil data dari database.
8. Jika butuh reasoning, data dikirim ke AI Router.
9. AI Router memilih model.
10. AI membuat jawaban.
11. Orchestrator memformat jawaban.
12. Telegram Bot mengirim response.
13. Semua request dan response disimpan ke logs.

============================================================
5. WORKFLOW SOP BOT
============================================================

Input:
User kirim:
'/sop cara handle komplain makanan terlambat'

Flow:
1. Telegram Bot menerima command.
2. Validasi user dan role.
3. SOP Engine mencari dokumen SOP di PostgreSQL.
4. Jika ditemukan, ambil SOP terkait.
5. Kirim context SOP ke AI Router.
6. AI membuat jawaban singkat dan praktis.
7. Jika SOP tidak ditemukan, jawab bahwa SOP belum tersedia dan log pertanyaan.
8. Telegram kirim jawaban.
9. Pertanyaan disimpan untuk evaluasi SOP.

Output:
SOP HANDLE KOMPLAIN MAKANAN TERLAMBAT
1. Minta maaf.
2. Cek status order ke kitchen.
3. Beri estimasi waktu baru.
4. Jika delay terlalu lama, tawarkan kompensasi sesuai SOP.
5. Catat komplain di laporan shift.

============================================================
9. WORKFLOW TRADINGVIEW WEBHOOK - SRI ICT
============================================================

Endpoint:
POST /tradingview/webhook

Contoh payload:
{
  "source": "tradingview",
  "pair": "XAUUSD",
  "timeframe": "M15",
  "signal": "MSS_BULL",
  "price": 4050.25,
  "session": "NY_SB",
  "timestamp": "2026-06-28T22:15:00+07:00"
}

Flow:
1. TradingView alert masuk ke backend.
2. Backend validasi webhook secret.
3. Simpan event ke trading_alerts.
4. Trading Engine baca signal.
5. Trading Engine cek state:
   - HTF Bias
   - DOL
   - Sweep
   - MSS
   - IFVG
   - SMT
   - Silver Bullet Time
   - News Block
6. Jika belum lengkap, kirim Telegram WAIT.
7. Jika lengkap, kirim Telegram VALID SETUP.
8. Semua event disimpan ke trading journal/log.

Output:
SRI ICT UPDATE
Pair: XAUUSD
TF: M15
Signal: MSS BULL
Session: NY SB
Status: WAIT
Next: Tunggu M5 IFVG Bull
Rule: No IFVG = No Entry


============================================================
10. WORKFLOW SRI ICT COMPLETE SETUP
============================================================

Sequence:
1. HTF Bias terbaca.
2. DOL jelas.
3. Liquidity sweep terjadi.
4. MSS muncul.
5. IFVG muncul.
6. SMT menjadi confluence tambahan.
7. Masuk waktu Silver Bullet.
8. Tidak ada high impact news.
9. Orchestrator kirim alert valid.

Rules:
No Sweep = No MSS.
No MSS = No Trade.
No IFVG = No Entry.

Output valid:
SRI ICT VALID SETUP
Pair: XAUUSD
Bias: BUY
Session: NY SB
HTF: Mixed
Sweep: SSL taken
MSS: Bull confirmed
IFVG: Bull confirmed
SMT: Bull
DOL: Buy Side
Action: Setup valid. Tunggu entry sesuai SOP.

11. WORKFLOW AI ROUTER
============================================================

Input:
- task_type
- user_message
- context
- preferred_model
- role
- priority

Routing awal:
- sop -> Qwen Local
- trading_reasoning -> GPT
- coding -> Claude
- image/screenshot -> Gemini
- fallback -> GPT

Flow:
1. Module kirim request ke AI Router.
2. AI Router cek task_type.
3. AI Router cek model availability.
4. Jika model utama gagal, pakai fallback.
5. Response dikembalikan ke module.
6. Log model, token, cost, error disimpan.

14. WORKFLOW BACKUP
============================================================

Jadwal:
Setiap hari jam 03:00 WIB.

Flow:
1. Worker menjalankan pg_dump PostgreSQL.
2. File disimpan lokal.
3. Optional upload ke cloud drive.
4. Simpan log backup.
5. Jika gagal, kirim Telegram alert.

Output:
YKP BACKUP STATUS
Backup: SUCCESS
Time: 03:00 WIB
File: backup_2026_06_28.sql
