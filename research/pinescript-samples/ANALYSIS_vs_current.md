## Review Verdicts

- GAP 1 (Timezone SB via input.session + IANA): KEEP. Verified — samples only use input.session without IANA TZ arg in time(); playerjohnson hardcodes America/New_York. v2 genuinely more robust. Claim accurate.
- GAP 2 (No-repaint nrSecurity exp[1]+lookahead_on): KEEP. Verified — only 3/20 samples use lookahead_on; none wrap it consistently. v2 wrapper is cleaner and applied uniformly. Claim accurate.
- GAP 3 (alert.freq_once_per_bar_close): KEEP. Verified — zero samples use once_per_bar_close; all use once_per_bar or default. v2 fix is real and superior for signal integrity.
- GAP 4 (MSS body-close break vs wick): KEEP. Valid ICT pattern, toggle-able. Low risk, real benefit.
- GAP 5 (Sweep TTL reset after MSS): KEEP. Pro pattern, prevents multi-MSS from one sweep. Sound.
- GAP 6 (FVG array FIFO + body mitigation): KEEP but DOWNGRADE claim. Not novel — 15/20 samples use box arrays. v2 is standard, not a v1-fix-from-research. Accurate as a refactor, overclaim as research-derived.
- GAP 7 (HTF BOS/CHoCH state machine vs HH/HL): MODIFY framing. MarcosACH/19 uses function-based CHoCH of equal sophistication. v2 inline var-int approach is an alternative, NOT superior. README 'more pro' framing overclaims — reword to 'alternative non-repaint implementation'.
- GAP 8 (SMT correlation filter |corr|>=0.6): MODIFY framing. Zero of 20 samples use ta.correlation for SMT — this is original work, not 'professional pattern research'. Keep the feature (genuine value: filters weak SMT), but drop the 'research-derived pro pattern' claim. Mark as v2-original addition.
- README claim 'Riset dari 8+ professional-grade repos': MODIFY. Changelog cites 8 repos but 4 (btankutt, 0xSHAK1B, jchi18, BAKOME) are absent from samples folder — cannot verify they informed the code. Either fetch those repos or reduce the citation list to the 4 actually present (yusin99, VitaHoang, craftzbay, orestefrison).
- FVG mitigation mode selector (body/wick/50pct) input: DROP. Only 'body' is implemented; wick/50pct are dead options ('reserved for future'). YAGNI — remove the input, hardcode body, add ponytail: comment naming the upgrade path. Dead config = complexity without benefit.
- PDH/PDL/PWH/PWL lines (toggle off default): KEEP. Pure optional visual, zero runtime cost when off, no complexity bloat. Fine.
- OB displacement ATR multiple input + max OB boxes: KEEP. Standard, useful, bounded.
- Duplicate FVG cap (lines 218-221 AND 238-241): DROP one. Dead code — the second cap block runs after push and is redundant with the first. Remove lines 238-241.
- News block moved to Orchestrator: KEEP. Correct boundary — Pine cannot fetch external API. Sound architectural call.
- Webhook JSON with bar_index dedup: KEEP. Genuinely useful for Orchestrator idempotency, not present in samples.

## Strengths to Preserve

- Explicit no-repaint tradeoff disclosure in README (1-bar lag) — keep this honesty, it is rarer than the code fix itself.
- All signal alerts funnel through one buildJson() function + single rising() guard — consistent, auditable, easy to extend.
- TTL/counter logic for sweep → MSS → IFVG is sound and prevents stale confluence triggers.
- Inputs are grouped and bounded (minval/maxval) — no unbounded user damage.
- Optional layers (OB, PDH/PDL) default off — good minimalism principle.

- Edit sri-ict-silver-bullet.pine: remove lines 238-241 (redundant FVG cap); remove i_fvgMitMode input and hardcode body-close; add ponytail comment for wick/50pct future upgrade.
